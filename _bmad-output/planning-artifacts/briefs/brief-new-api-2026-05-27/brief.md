# 产品简报：`{NEW_PRODUCT_NAME}` 企业演进（基于 new-api）

> **命名说明**：本演进将以新产品名独立发行（具体名称 TBD）；底层代码基于 QuantumNous/new-api，受保护标识保留不动。文中以 `{NEW_PRODUCT_NAME}` 作为占位符。

## 执行摘要

**new-api**（由 QuantumNous 维护的开源 AI API 网关）已经具备扎实的核心能力：聚合 40+ AI 供应商、用户/Token/计费/限流/订阅/支付/OAuth 等完整商业化基础。**本简报聚焦 `{NEW_PRODUCT_NAME}` 的下一阶段演进**——将单实例 AI 网关升级为面向中国企业客户的「企业级 AI 中台 + 平台化能力 + 可选 SaaS 形态」组合产品。

演进核心是三条主题线并行推进：**企业管控**（组织化、钉钉集成、用量与合规）、**平台能力扩展**（代码库 DeepWiki、增强 WebChat、图像/视频生成）、**商业模式延展**（SaaS 多租户、上游服务商增值）。三条线在底层共享同一份组织/租户数据模型，使「企业自部署」和「SaaS 托管」可以在同一代码基线上交付。

**为什么是现在：** 国内企业 AI 引入正从"试用"进入"集团化部署 + 合规管控"阶段，现有 new-api 的商业化基础设施已足够支撑这一跃迁。

> **本简报术语约定**：
> - **上推（QuantumNous）**：将能力以 PR 形式贡献回 QuantumNous/new-api 上游开源仓库
> - **独占（`{NEW_PRODUCT_NAME}`）**：能力仅在 `{NEW_PRODUCT_NAME}` 发行版中维护，不回流开源
> - **三级倍率**：模型倍率 × 用户分组倍率 × 分组间倍率（group-to-group ratio）

---

## 核心缺口（驱动本演进）

new-api 现有能力详见附录 A。本演进锚定的 4 项关键缺口：

1. 无真正的组织/租户层级——只有单维的 `Group` 字符串标签
2. 无中国企业 IdP 集成（钉钉/飞书/企微）
3. 平台能力局限于 API 代理，缺乏代码库可视化与多模态生成的开箱即用入口
4. 部署模型单一，未抽象出 SaaS 多租户语义

---

## 演进定位

**双轨产品：以企业自部署为优先交付，SaaS 形态作为后置阶段。**

- **企业自部署版**：面向有数据安全/合规要求的企业，以钉钉为认证主入口，组织树由钉钉通讯录同步
- **SaaS 托管版**：面向不愿自部署的小型团队/创业公司，提供多租户隔离、独立工作空间、按量付费
- **上游服务商定位**：同时面向"已自部署 new-api 的客户"提供 Token 批发、运维托管、培训咨询等增值服务

**商业模式**：开源核心（钉钉登录、组织/部门模型、内容监控等通用能力上推 QuantumNous）+ 企业版增值能力（代码库 DeepWiki、企业知识库、SaaS 平台等）由 `{NEW_PRODUCT_NAME}` 独立维护。

---

## 三大主题线

### 🏢 主题 A：企业管控

**目标：** 把 new-api 从"个人/小团队工具"升级为"集团 IT 可治理的 AI 中台"。

| 能力 | 描述 |
|---|---|
| 组织/部门层级 | 引入 `Organization` 数据模型，配额可按部门分配、用量按部门聚合 |
| 钉钉企业集成 | 钉钉 OAuth 登录 + 通讯录同步（自动建账号、自动归属部门） |
| 组织用量看板 | 部门级用量统计、CSV 导出、定期邮件报告 |
| 内容监控告警 | 现有过滤基础上补充：违规率监控、告警通知（钉钉/邮件） |

**业务价值：** 企业 IT 第一次能回答"哪个部门花了多少 AI 额度、用在了什么模型上、有没有违规"。

### 🧠 主题 B：平台能力扩展

**目标：** 从「API 代理」演进为「企业可直接使用的 AI 工作平台」。

| 能力 | 描述 |
|---|---|
| 代码库 DeepWiki | 类 deepwiki.com 形态：连接企业内部 Git 仓库，AI 辅助生成可视化代码地图、架构索引、模块问答；面向研发团队的"代码理解加速器" |
| WebChat 增强 | 在现有 Playground 基础上扩展：接入代码库知识、图像生成、多模态输入 |
| 图像/视频生成 | 链接到开源项目（如 ComfyUI / SD WebUI），由 `{NEW_PRODUCT_NAME}` 透传用户 API Key，提供"一键打开生成工具"入口 |

**业务价值：** 研发团队不必跨多个工具就能完成"读代码 + 问 AI + 生成内容"的工作流；管理员不必为每个工具单独配置权限/计费。

**注：** 通用企业文档库（非代码）作为主题 B 的二期可选扩展，本简报范围不强约束。

### 💼 主题 C：商业模式延展（后置）

**目标：** 在企业自部署版稳定后，开放 SaaS 形态和服务化能力。

| 能力 | 描述 |
|---|---|
| SaaS 多租户 | 基于主题 A 的组织模型，扩展为公网租户隔离 + 独立工作空间 |
| 上游服务商增值 | Token 批发计费、运维监控托管、培训咨询打包销售 |

**业务价值：** 把企业版能力以更轻的方式触达中小客户；同时承接"用 new-api 但不想运维"的存量需求。

---

## 关键差异化

1. **棕地优势：现成的计费/限流/多供应商体系**——竞品要从零搭，`{NEW_PRODUCT_NAME}` 只需在上层扩展
2. **中国企业本地化**：钉钉/飞书/企微深度集成，不是把海外 IdP 简单替换
3. **代码库 DeepWiki 切入点**：相比通用文档库 RAG 拥挤的赛道，面向研发团队的"代码理解 + AI 问答"是更聚焦的入口
4. **双轨灵活性**：同一代码基线既能私有部署，也能 SaaS 托管，客户路径无锁定
5. **诚实声明**：本简报范围内**没有**模型层壁垒（推理性能、独家模型等）——壁垒在**业务集成深度**与**商业化执行**

---

## 服务对象

**主要：**
- **中型企业 IT 负责人**：要给全公司开 AI 能力，但需要可治理、可审计、可分摊成本
- **企业研发团队负责人**：希望团队用 AI 加速代码理解、上手新仓库、跨模块协作
- **集团内部应用团队**：需要在企业基础设施内调用 AI API，不能用公网服务

**次要：**
- **小型团队 / 早期创业公司**：不想自部署，愿意付费用 SaaS 形态
- **已自部署 new-api 的客户**：希望购买 Token 批发 / 运维托管 / 培训等增值服务

## 成功标准

**V1（企业管控）：**
- 至少 1 家企业完成钉钉登录 + 部门同步 + 部门级用量看板的闭环验证
- 部门级配额分配在生产环境无超额/漏算事故 30 天

**V2（平台扩展）：**
- 代码库 DeepWiki 上线 → 至少 1 家试点企业的研发团队 30 天内活跃使用（具体活跃口径在 PRD 阶段定义）
- WebChat 替代至少 1 类原有外部工具（如 ChatGPT 网页版）

**V3（SaaS）：**
- 至少 1 个 SaaS 租户付费在线 30 天，无跨租户数据泄漏事故

**横向：**
- 企业版相对开源版的功能差异，能被销售清晰讲述（避免"商业版到底卖什么"的模糊）
- 代码贡献回 QuantumNous 上游不设硬指标，按 case 决定

## 范围分期

### V1 — 企业管控基线（6-8 周）
- ✅ 组织/部门数据模型
- ✅ 钉钉 OAuth 登录 + 通讯录同步
- ✅ 部门级配额与用量看板
- ✅ 内容监控告警（基于现有过滤）
- ✅ 飞书/企微作为同模式的二期适配（结构预留）

### V2 — 平台能力（8-12 周）
- ✅ 代码库 DeepWiki（Git 仓库接入 + 可视化 + 问答）
- ✅ WebChat 增强（代码库知识接入 + 多模态）
- ✅ 图像/视频生成入口（链接到开源工具 + Key 透传）
- ⏳ 通用企业文档库 RAG（二期可选）

### V3 — SaaS + 服务化（独立立项，>3 个月）
- 多租户隔离（数据/UI/路由）
- 公共注册 + 工作空间
- Token 批发 + 运维托管 SLA + 培训咨询包

### 明确不做（本演进周期内）
- D：API Key 管控策略扩展（强制过期、轮换提醒）
- H：私有化授权 License 机制
- A：专用审计日志表
- 通用 LDAP/SAML/SCIM

> 详细理由见附录 C.1。

## 战略风险（Top 3）

| 风险 | 影响 | 缓解 |
|---|---|---|
| **代码库 DeepWiki 形态新颖，需求验证不足** | V2 主打能力卡壳 | V2 启动前做 1-2 家试点企业的需求访谈；优先支持主流 Git 平台（GitHub/GitLab/Gitee） |
| **多租户晚做付出重构成本** | V3 启动时数据模型大改 | V1 的 `Organization` 模型预留 `tenant_id` 字段，即使 V1/V2 不启用 |
| **双轨模式拉扯研发资源** | V1/V2 拖期 | V3 单独立项；前两版严格不为 SaaS 让步设计 |
