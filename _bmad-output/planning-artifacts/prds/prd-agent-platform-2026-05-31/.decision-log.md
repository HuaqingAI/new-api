# Decision Log — prd-agent-platform-2026-05-31

## 2026-05-31

- Source trigger:
  - User requested a new planning batch for downstream agent tools.
  - Scope must be generic and reusable.
  - Cherry Studio enterprise extension is the first validating consumer, not the only or canonical consumer.
  - Skill library, knowledge library, and agent library are not API-only resources; they require frontend admin pages and backend management logic.

- Planning decision:
  - Do not extend the existing enterprise-governance PRD as the primary home for this scope.
  - Create a separate planning track for a generic agent capability platform.

- AP-6 clarification:
  - AP-6 is not a Cherry Studio-specific channel adapter epic.
  - AP-6 is the standard extension layer for the project's existing OpenAPI / open capability surface.
  - Cherry Studio is only the first validating consumer of that standard layer.

- Document strategy:
  - Create a dedicated PRD, architecture document, and epics document for the agent-platform track.
  - Keep enterprise-governance artifacts as foundational but separate.

- 2026-05-31 PRD refinement decision:
  - User approved handling all previously identified P0 and P1 PRD issues under the BMAD PRD standard.
  - PRD was updated to:
    - lock primary and secondary users,
    - reframe the core problem as business pains instead of only platform-unification language,
    - convert MVP from a module list into a validating end-to-end closed loop,
    - add role boundaries, glossary discipline, and evidence-bearing user journeys,
    - treat Agent MVP scope as "definition and reference object" rather than complex runtime execution,
    - add cross-cutting NFRs, compatibility/deprecation expectations, and success/counter metrics,
    - replace generic open questions with pre-architecture decision gates.

- 2026-05-31 PRD convergence fix:
  - User approved directly fixing the validation findings in the PRD.
  - Knowledge MVP scope was locked to a single standardized `retrieval` mode.
  - Cache/revoke/rollback semantics were tightened with a 5-minute TTL upper bound and explicit client convergence window.
  - MVP closed-loop wording was aligned with success metrics so `Skill`, `Knowledge`, and lightweight `Agent` validation all sit in the same acceptance frame.
  - `Agent` validation was promoted from implicit scope to explicit measurable success criteria.
  - Prior “first consumer”, “AP-6 basis”, and “Agent as definition object” statements were treated as explicit PRD decisions rather than lingering assumptions.
