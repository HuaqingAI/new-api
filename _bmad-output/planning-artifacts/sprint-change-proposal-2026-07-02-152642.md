# Sprint Change Proposal

## 1. 问题摘要

本次纠偏由 2026-07-02 的 4 个开放 issue 与一条现场权限反馈共同触发：

- `#24`：钱包页订阅优先级调整与“优先订阅”实际效果不一致
- `#29`：额度申请页周期预算池出现异常负剩余额度
- `#30`：取消额度后预算池/订阅余额未回退
- `#31`：企业分配钱包状态与有效期/额度展示矛盾
- 现场补充：超级管理员将用户设为管理员后，该用户仍无法正常访问管理员菜单与页面

当前判断这不是新需求，而是 Epic 3 / Epic 7 / Epic 7A 落地后的实现偏差与生命周期一致性问题。

## 2. 影响分析

### Epic Impact

- **Epic 3: 部门预算池与成员 Wallet 分配**
  - 预算池 `remaining / allocated_total / cycle_quota` 的展示与治理回退必须重新对齐。
  - 通用订阅管理入口不应绕开企业 allocation 的账务回退链路。
- **Epic 7: 分层预算治理与额度审批**
  - allocation 取消/撤销/回收必须坚持“企业治理入口是唯一真入口”。
- **Epic 7A: 企业治理体验纠偏**
  - 企业钱包状态、有效期和可排序性需要与既定 UX 语义重新收敛。
- **平台通用账号治理**
  - Default 用户管理页编辑角色能力与角色生效链路存在缺口。

### Artifact Conflicts

- **PRD / Architecture**
  - “企业钱包默认在前，但用户可调整顺序”与当前后端硬编码排序边界冲突。
  - “取消/撤销应保留审计并正确回退预算”与通用订阅失效入口当前行为冲突。
- **UX**
  - 状态为“已过期”时不能同时显示“永不过期”。
  - 周期池剩余额度异常时，应至少收敛为 `0` 和明确不足语义，而不是继续暴露负数给申请入口。

## 3. 推荐路径

推荐采用 **Option 1: Direct Adjustment（低到中风险）**：

- 不重做 Epic 结构，不回滚既有企业模块；
- 通过修正会话鉴权、用户角色编辑、企业钱包保护、预算池显示归一化、订阅排序边界来闭环；
- 同时补回归测试，避免后续再次通过“通用订阅管理”绕过企业治理账务。

不建议走回滚或 PRD 缩 scope：

- 问题集中在实现偏差，而非需求本身不可行；
- 现有企业治理架构仍成立，修复点局部且可验证。

## 4. 详细变更提案

### 4.1 用户角色编辑与生效链路

**OLD**

- Default 用户编辑抽屉更新时不提交 `role`
- 后端 `UpdateUser -> user.Edit()` 也不会真正更新 `role`
- session 鉴权长期使用旧 `role`，提权后需要重新登录或命中新会话

**NEW**

- Default 用户编辑抽屉在更新模式下允许编辑普通用户 / 管理员角色
- 后端更新用户时实际写入 `role`
- session 鉴权每次以数据库中的当前用户角色/状态为准，并自动刷新 session 中旧字段
- `_authenticated` 路由每次进入时刷新 `getSelf()`，同步前端缓存角色

**Rationale**

这条修改直接解决“设置为管理员后仍提示权限不足”的双重根因：前端没真正改角色、后端/前端又继续使用旧 session / 旧缓存。

### 4.2 企业钱包不得通过通用订阅失效入口处理

**OLD**

- 企业派生钱包禁止 `Delete`
- 但仍可从通用“订阅管理”中执行 `Invalidate`
- 该路径不会同步企业预算池回退，容易造成 `#30`

**NEW**

- 后端 `AdminInvalidateUserSubscription` 对企业派生钱包直接拒绝
- 前端订阅管理弹窗对企业派生钱包禁用 `Invalidate`
- 引导继续通过企业治理 / allocation 入口撤销

**Rationale**

企业 allocation 的预算回退、审计快照、状态语义只能由企业治理链路维护，通用订阅入口不应破坏这一单一事实来源。

### 4.3 预算池剩余额度展示归一化

**OLD**

- 周期预算池列表 / capability / 详情直接回传持久化 `remaining`
- 若历史数据曾出现 `remaining < 0`，额度申请页直接显示巨大负数

**NEW**

- 读取周期预算池时统一按 `max(cycle_quota - allocated_total, 0)` 归一化展示
- 余额型预算池展示时至少裁到 `[0, total_quota]`

**Rationale**

这满足 issue `#29` 的用户侧期望：异常场景至少显示为 `0` 或明确不足，而不是继续暴露负数。写路径保持现有铁律，读路径先对历史脏数据做安全收敛。

### 4.4 企业钱包排序语义纠偏

**OLD**

- 后端排序把企业钱包与普通订阅切成不同优先级组
- `Move Up / Move Down` 只能在组内移动，无法真正跨越企业钱包边界

**NEW**

- 企业钱包只保留“默认创建时排前”的初始 `sort_order`
- 后续排序与计费选择统一按全局 `sort_order` 解释，不再硬编码企业钱包永久锁前

**Rationale**

这与规划文档一致：企业钱包默认前置，但用户可调整顺序。否则 issue `#24` 的“按钮点了没明显变化”会持续存在。

### 4.5 企业钱包状态与有效期文案纠偏

**OLD**

- 非正 `end_time` 的企业钱包只要来源是 enterprise allocation，就可能被渲染成“永不过期”
- 即使该钱包状态已经不是 active，UI 仍可能显示“至永不过期”

**NEW**

- 只有 `active` 的企业派生钱包才把非正 `end_time` 解释为“永不过期”
- 非 active 状态下改为 `Expired at / Cancelled at + No expiry set`

**Rationale**

解决 issue `#31` 中“状态已过期，但有效期显示永不过期”的自相矛盾文案。

## 5. 实施交接

### Scope Classification

**Moderate**

- 需要修改 Go 后端鉴权 / 订阅 / 企业预算治理逻辑
- 需要同步 Default 前端角色编辑、会话刷新、企业钱包交互
- 不需要重做产品范围或重排 Epic

### Handoff

- **Developer**
  - 实施角色更新、session 同步、企业钱包保护、预算展示归一化、排序语义修正
  - 补 Go / TS 回归测试
- **PO / PM**
  - 无需重写 PRD，仅确认“企业钱包默认前置但可调整顺序”的既定语义继续有效

### Success Criteria

- 被提权用户无需重新登录即可在下一次受保护请求中获得管理员权限
- 企业派生钱包不能再从通用订阅管理入口被直接失效
- 周期预算池在额度申请入口不再显示负剩余额度
- 企业钱包不再出现“已过期 + 永不过期”的矛盾文案
- 订阅排序调整能真正影响全局展示与扣费顺序
